# Stilleben

Modern snapshot testing written in Swift.

Used to for testing snapshots of mostly UI components but also models and other types.

It comes with a few predefined matchers:
- `UIMatcher` for SwiftUI and UIKit snapshots.
- `EncodableMatcher` for snapshots of models encoded to JSON.
- `ReflectionMatcher` for snapshots of any type in the form of a reflection description.

Snapshots can be configured to use the following:
- `RecordingStrategy` determines how snapshots are saved and read.
- `DiffingStrategy` how to diff the recorded snapshot against the one generated by the test.
- `RenderingStrategy` strategy used for rendering UI snapshots.
- `SizingStrategy` strategy used for sizing views before snapshotting: `.device`, `.dynamicHeight`, `.fullWidth`, `.fixedHeight(_:)` or `.intrinsic`. Each decides whether the snapshot ignores the device's safe area: all but `.device` do by default, and every strategy takes `ignoresSafeArea:` to change that, like `.dynamicHeight(ignoresSafeArea: false)`.

UI snapshots are laid out and rendered for a configured `Device` (size, display scale, safe area and traits),
so they look the same on any simulator. Presets include `.iPhone18Pro` (default), `.iPhone18ProMax`, `.iPhone17e`, `.iPhoneDuo` and `.iPhoneDuoFolded` (unfolded and folded) and `.iPadPro13`.
Snapshots are permuted over `devices(...)`, and each snapshot name includes the device class (`phone`, `pad`, ...),
which stays the same when a preset moves to a newer model.

## Requirements

- iOS 26 and Swift 6.4 (Xcode 27).
- UI snapshots work in tests hosted in an app and in tests of Swift packages; see the tradeoffs below.
- Stilleben runs on the main actor: mark snapshot test classes `@MainActor`.

## Hosted and unhosted tests

UI snapshots work both in tests hosted in an app and in tests of Swift packages, which run without an app.
Which one to use is up to you:

| | Hosted (test host app) | Unhosted (Swift package tests) |
|---|---|---|
| Setup | Needs an app target as test host | Works in any package test target |
| Window | In the app's window scene | Standalone window without a scene |
| Rendering | Draws the view hierarchy, like the screen | Renders the layer tree |
| Liquid Glass (tab bars, glass buttons and bars) | Rendered | Glass content is missing, only its outline is drawn |
| Rounded corners (e.g. grouped lists) | Rendered | Anti-aliased slightly differently, so references differ from hosted ones |
| Everything else | Rendered | Identical to hosted |

References are recorded in the mode the tests run in, so keep each test target in one mode. Snapshot views that use
Liquid Glass in hosted tests if the glass itself matters.

## Localization

`UIMatcher().locales(...)` takes a snapshot per locale, and strings are localized however the views look them up:
SwiftUI `Text` through the `\.locale` environment, and `NSLocalizedString`, `String(localized:)`,
`LocalizedStringResource` and `Bundle.localizedString` through `Bundle`, for String Catalogs and `.strings` files in
the app or in Swift packages alike. Number and date formatting that uses `Locale.current` is not changed.

## Simulator

The device configuration sets the size, scale and traits of a snapshot, but rendering still differs between iOS versions
and simulators (fonts, anti-aliasing, system components). Pin the simulator with
`assertSimulator(modelIdentifier:osVersion:)`: on any other simulator the test fails before anything is compared or
recorded, so references are never overwritten with a different rendering.

## Examples

Example of snapshot testing a SwiftUI view:
```swift
import XCTest
import Stilleben

@MainActor
final class SomeViewTests: XCTestCase {
    private let matcher = UIMatcher()
        .assertSimulator(modelIdentifier: "iPhone19,2", osVersion: "27.2")
        .devices(.iPhone18Pro)
        .sizing(.dynamicHeight)
        .dynamicTypeSizes(.large)

    func testSomeView() async throws {
        await matcher
            .colorSchemes(.light)
            .match {
                NavigationView {
                    SomeView()
                }
            }
    }
}
```

It also supports snapshot testing UIKit view controllers or views:

```swift
import XCTest
import Stilleben

@MainActor
final class SomeViewControllerTests: XCTestCase {
    private let matcher = UIMatcher()
        .assertSimulator(modelIdentifier: "iPhone19,2", osVersion: "27.2")
        .devices(.iPhone18Pro, .iPadPro13)
        .sizing(.device)

    func testSomeViewController() async throws {
        await matcher
            .match { () -> UIViewController in
                SomeViewController()
            }
    }

    func testSomeView() async throws {
        await matcher
            .sizing(.intrinsic)
            .match { () -> UIView in
                SomeView()
            }
    }
}
```

Support for snapshotting reflections of your models:

```swift
import XCTest
import Stilleben

@MainActor
final class ReflectionTests: XCTestCase {
    let matcher = ReflectionMatcher()

    func testSimpleModel() async {
        struct Model {
            let text = "Hello World!"
        }

        await matcher.match {
            Model()
        }
    }
}
```

Which yields a text file snapshot:

```
  ▿ StillebenTests.ReflectionTests.?.?.Model
    - text: "Hello World!"
```

## Recording

`RecordMode` decides when reference snapshots are written:

| Mode | Missing reference | Different snapshot |
|---|---|---|
| `.failed` (default) | Recorded, test fails | Reference overwritten, test fails |
| `.missing` | Recorded, test fails | Test fails |
| `.never` | Test fails | Test fails |
| `.all` | Always recorded, test fails | Always recorded, test fails |

With `.failed`, a changed snapshot shows up as a diff in git, ready to review and commit or discard. Set it per matcher with
`UIMatcher().record(.never)`, or for a whole run with the `STILLEBEN_RECORD` environment variable (CI uses `never`).

## Development

Tools are pinned with [mise](https://mise.jdx.dev). `scripts/verify.sh` formats the code, fails if that leaves changes,
and runs the tests. CI runs the same script. Generate the test host project with `mise exec -- xcodegen` in `TestHost/`
and open it: its `Stilleben` test plan runs the package tests (unhosted) and the few snapshots that need a window scene
(hosted in the TestHost app) together. Opening `Package.swift` runs only the package tests.
